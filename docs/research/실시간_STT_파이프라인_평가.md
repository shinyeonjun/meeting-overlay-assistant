# 실시간 STT 파이프라인 평가 (2026-10)

회색 자막(partial)은 NVIDIA Nemotron 3.5 streaming, 확정 시점은 Silero VAD(무음 300ms, 최대 구간 12초), 확정 자막(final)은 faster-whisper turbo로 구성하고 동시 세션을 2개로 제한하는 것이 측정 범위 안에서 가장 균형이 좋다.

이 문서는 2026-10-12~13에 노트북 GPU 한 대에서 수행한 실시간 STT 평가의 방법, 수치, 한계를 기록한다. 제품 기준 문서가 아니며, 파이프라인 변경을 결정할 때 근거 자료로 쓴다.

## 1. 배경

현재 라이브 STT는 회색 자막에 sherpa-onnx 한국어 streaming zipformer를, 확정 자막에 faster-whisper large-v3-turbo를 쓴다. 확정 구간은 에너지 기반 VAD(`VadSpeechSegmenter`, 기본 무음 450ms, 최대 구간 5초)가 자른다.

이번 평가는 아래 세 질문에 답하기 위해 수행했다.

1. 허깅페이스에 현재보다 나은 한국어 실시간 모델이 있는가
2. 확정 시점을 어떻게 정해야 정확도와 지연이 균형을 이루는가
3. 회색·확정 두 모델이 한 GPU를 같이 쓸 때 밀림이 생기는가

인코더-디코더 구조(Whisper 계열)는 실시간 회색 자막에 맞지 않는다는 전제로, 회색 자막 후보는 스트리밍 전용 구조(RNN-T, transducer)로 한정했다.

## 2. 평가 환경

| 항목 | 값 |
|---|---|
| GPU | NVIDIA GeForce RTX 5070 Laptop (8GB) |
| 확정 모델 | `deepdml/faster-whisper-large-v3-turbo-ct2`, CTranslate2 4.8.2, `int8_float16`, beam 1 |
| 회색 후보 | `nvidia/nemotron-3.5-asr-streaming-0.6b` (638M, cache-aware FastConformer RNN-T), transformers 5.19 `AutoModelForRNNT`, `language="ko-KR"` |
| 회색 현행 | `sherpa-onnx-streaming-zipformer-korean-2024-06-16`, CPU 2스레드, `modified_beam_search` |
| VAD | 제품 `VadSpeechSegmenter`, Silero VAD 6.2.3 (`VADIterator`, threshold 0.5) |
| 평가용 별도 환경 | `D:\stt_eval\venv` (Python 3.12, torch 2.11.0+cu128). 프로젝트 venv는 변경하지 않았다 |

Nemotron은 NeMo의 오프라인 `transcribe()` 경로에서 언어 프롬프트가 전달되지 않아(`Unknown prompt key: 'None'`) 쓰지 못했다. 모델 카드의 transformers 경로(`processor(..., language="ko-KR")`)로 평가했다.

## 4. 지표 정의

- **CER**: 한글·영문·숫자 외 문자를 지우고 소문자로 맞춘 뒤 글자 단위 편집 거리를 정답 길이로 나눈 값. 낮을수록 좋다. Nemotron이 붙이는 언어 태그(`<ko-KR>`)는 채점 전에 지운다.
- **RTF**: 처리 시간 ÷ 음성 길이.
- **확정 지연**: (구간을 내보낸 시각 − 그 구간의 실제 마지막 발화 끝) + faster-whisper 처리 시간. 실제 발화 끝은 잡음 없는 원본의 30ms 프레임 RMS로 구한다.
- **회색 밀림**: Nemotron이 입력 청크를 예정 시각(실시간 기준)보다 늦게 가져간 시간.

### 5.2 sherpa의 음량 민감성

원본 음량 그대로 넣으면 sherpa는 40개 중 18개 클립에서 거의 아무 글자도 내지 않았다(글자 0~4개). 실패 클립의 평균 RMS는 0.0023, 성공 클립은 0.0201이다. 엔드포인트 감지를 끄거나 끝에 무음 1.5초를 붙여도 결과는 같았고, 피크 정규화만 CER을 0.576에서 0.210으로 낮췄다.

faster-whisper는 같은 정규화에서 오히려 0.048 → 0.056으로 나빠졌다. 음량 정규화는 모델별로 효과가 다르다.

- 동시 세션 2개까지는 회색과 확정 모두 밀림이 없고, 3개부터 회색 자막이 최대 1.2초 밀린다.
- 한 Nemotron 모델 객체를 여러 스레드가 동시에 `generate()` 하면 내부 상태가 덮여 `AttributeError`가 난다. 세션별 인스턴스나 멀티 스트림 배치 처리(NeMo `CacheAwareRNNTPipeline`)가 필요하다.
- 첫 측정에서 워밍업 없이 돌린 세션 0개 조건은 p90이 2.31초로 나왔다. 서버 기동 시 워밍업이 필요하다는 근거다.
- 이 측정의 확정 구간은 에너지 VAD(무음 450ms)로 잘랐다. 추천 구성 조합은 5.7에서 다시 쟀다.

### 5.9 회색 자막이 확정되면서 얼마나 바뀌나 (스트림 6개, 잡음 없음)

Silero(300ms, 12초) 구간 75개마다 Nemotron 결과(회색)와 faster-whisper 결과(확정)를 정규화한 뒤, 글자 편집 거리를 확정 글자 수로 나눈 값(변경률)을 쟀다.

| 지표 | 값 |
|---|---|
| 변경률 평균 | 10.0% |
| 변경률 중앙값 | 4.8% |
| 변경률 p90 | 15.9% |
| 변경률 10% 미만 구간 비율 | 74.7% |
| 변경률 30% 초과 구간 비율 | 4.0% |
| 구간당 평균 글자 수 | 27.3자 |

- 구간 네 개 중 세 개는 확정되면서 10% 미만만 바뀐다. 구간당 약 27자 기준으로 대개 1~3글자 수준이다.
- 30% 넘게 바뀌는 구간은 4%다. 이 구간에서는 회색 자막이 크게 바뀌어 눈에 띌 수 있다.

### 5.10 음량 변화와 실시간 음량 정규화 (스트림 6개)

발화마다 음량을 -30~0dB로 무작위로 바꿔 마이크 거리 차이를 흉내 냈다. 실시간 음량 정규화는 30ms 프레임 단위 인과적 AGC(목표 RMS 0.08, 최대 증폭 +30dB)다.

| 조건 | 확정 CER | 회색(Nemotron) CER | 지연 평균 | 지연 p90 |
|---|---|---|---|---|
| 정규화 없음 | 0.082 | 0.116 | 0.56초 | 0.74초 |
| 실시간 AGC | 0.078 | 0.114 | 0.62초 | 0.81초 |

- Silero, Nemotron, faster-whisper 조합은 음량 변화에 강하다. AGC의 효과는 CER 0.002~0.004로 작고, 지연은 약 0.07초 늘어난다.
- 음량에 민감했던 것은 sherpa였다(5.2). 추천 구성에서는 AGC를 필수로 넣을 필요가 없다.

## 6. 결론: 추천 구성

| 항목 | 선택 | 근거 |
|---|---|---|
| 회색 자막 | Nemotron 3.5 streaming, bf16, lookahead 6 | FLEURS CER 0.085, sherpa 0.210 대비 약 2.5배 정확 (5.1) |
| 확정 시점 | Silero VAD, 무음 300ms, 최대 구간 12초 | 평균 CER 0.082, 지연 p90 0.50초, 잡음에 강함 (5.5) |
| 확정 자막 | faster-whisper turbo 유지 | 단독 CER 0.048로 가장 정확 (5.1) |
| 음량 | AGC 필수 아님 | 추천 구성은 음량 변화에 강하고 AGC 효과는 CER 0.004 이하 (5.10) |
| 동시 세션 | 최대 2개 (RTX 5070 Laptop 기준) | 3개부터 회색 자막이 최대 2초 밀림 (5.6, 5.7) |
| 기동 | 두 모델 워밍업 필수 | 워밍업 없으면 첫 확정 지연이 2초 이상 (5.6) |

확정 자막 허용 지연 목표는 2초로 두었다. 위 구성은 잡음이 없거나 정적 잡음·짧은 끼어들기 조건에서 실시간으로도 1초 목표를 만족한다(5.7, 5.8). 배경 잡담(babble) 조건에서는 정확도와 지연 모두 목표를 넘는다(5.8). 이것이 다음 개선의 핵심이다.

회색 자막은 확정되면서 구간의 75%에서 10% 미만만 바뀐다(5.9). 회색→확정 2단계 표시는 UX상 무리가 없다.

## 7. 한계

- FLEURS는 낭독체다. 끊기고 겹치는 회의 대화에서는 모든 모델의 CER이 올라갈 수 있다.
- babble은 FLEURS 낭독 음성을 겹쳐 만든 것이다. 실제 회의실 잡담과는 말투와 공간감이 다르다.
- 스트림의 클립 사이 무음은 디지털 무음(0)에 잡음만 더한 것이다. 실제 마이크 입력의 반향과 자동 이득 조절은 반영되지 않았다.
- Silero의 CPU 사용량은 따로 재지 않았다. 세션 3개에서 회색 밀림이 커진 원인이 CPU 경합인지는 추정이다.
- 다른 프로그램(예: 로컬 LLM 서버)이 GPU를 같이 쓰는 조건은 측정하지 않았다.
- 측정은 RTX 5070 Laptop 한 대 기준이다. 동시 세션 한도는 GPU에 따라 달라진다.
- Nemotron 라이선스는 `openmdw-1.1`이다. 모델 카드에는 상업 사용이 가능하다고 적혀 있지만, 도입 전에 조건을 직접 확인해야 한다.

- `STT_MANIFEST`: 평가 목록 JSON 경로 (없으면 합성 회의 음성 3개)

## 9. 후속 작업

1. 배경 잡담(babble) 대응은 보류한다. 주 사용처는 온라인 회의(시스템 오디오)이고, 여기서는 동시 발화도 받아 적어야 할 내용이며 회의 앱이 참가자별 잡음 제거를 이미 한다. 대면 회의(마이크) 지원이 중요해지면 상대 음량 게이트, Silero 임계값 조정, 신뢰도 필터, 최대 구간 8초를 먼저 측정하고, 그다음 DeepFilterNet(VAD 입력 한정), 등록 화자 필터 순으로 검토한다. RNNoise는 babble을 거의 줄이지 못하므로 후보에서 뺀다.
2. 다른 프로그램이 GPU를 같이 쓸 때의 동시 세션 한도를 잰다.
3. 별도 브랜치에서 라이브 파이프라인을 바꾼다: 회색 자막 백엔드 교체, 확정 구간 VAD를 Silero로 교체, 동시 세션 한도 2, 기동 워밍업.
4. 바꾼 뒤 실제 오버레이→서버 경로의 끝단 지연과 30~60분 장시간 안정성을 잰다.
5. 확정된 내용은 `docs/architecture/`와 [하이브리드 STT 전략](하이브리드_STT_전략.md)에 반영한다.
