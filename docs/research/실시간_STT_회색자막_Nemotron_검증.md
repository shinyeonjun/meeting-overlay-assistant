# 회색 자막 Nemotron 전환 실서버 검증 (2026-10-13)

회색 자막(preview/live_final) 엔진을 sherpa-onnx에서 NVIDIA Nemotron streaming으로 바꾸고, 같은 서버·같은 음성·같은 절차로 두 엔진을 나란히 잰 결과다. 확정 자막(faster-whisper turbo + Silero 분할)은 두 경우 모두 같다.

테스트 음성(FLEURS 한국어 스트림 6개, 30분 연속 음성), 채점(CER), 서버 기동, 재생 방식은 [실시간 STT 실서버 검증](실시간_STT_실서버_검증.md) 4~5장과 같다. 이 문서는 달라진 것만 적는다.

## 1. 요약

| 항목 | sherpa | Nemotron |
|---|---|---|
| 회색 자막 정확도 (스트림 6개 평균) | 60.9% (CER 0.391) | **86.9%** (CER 0.131) |
| 회색 자막 첫 글자 (말 시작 → 첫 회색 자막) | 평균 917ms, p90 2,273ms | **평균 548ms, p90 973ms** |
| 회색 자막이 한 번도 안 나온 말소리 구간 | 10 / 115 | **2 / 115** |
| 확정 자막 정확도 | 91.5% | 91.5% (같음) |
| 말 끝 → 확정 도착 | 중앙값 892ms, p90 1,028ms | 중앙값 848ms, p90 1,046ms (같은 수준) |
| 늦은 확정 | 0 | 0 |
| 30분 연속: 확정 정확도 / 늦은 확정 | 92.1% / 0 | 92.0% / 0 |
| 30분 연속: 확정 작업 대기 | 0ms | 평균 약 310ms, 최대 625ms (쌓이지 않음) |
| 서버 메모리 | 약 1,050MB | 약 2,300MB |
| GPU 메모리 | 3,142MB | 4,476MB (30분 뒤 4,518MB) |

회색 자막은 정확도와 첫 글자 속도가 모두 크게 좋아졌고, 확정 자막의 정확도와 속도는 그대로다. 대가는 메모리(서버 +1.25GB, GPU +1.3GB)와 확정 작업 대기 약 0.3초다.

## 2. 구성

| 항목 | sherpa | Nemotron |
|---|---|---|
| 프로필 (`STT_BACKEND_SYSTEM_AUDIO`) | `hybrid_local_streaming_sherpa` | `hybrid_local_streaming_nemotron` |
| 회색 자막 모델 | `sherpa-onnx-streaming-zipformer-korean-2024-06-16` (CPU) | `nvidia/nemotron-3.5-asr-streaming-0.6b` (CUDA, bfloat16, lookahead 6) |
| 확정이 나올 때 회색 자막 엔진 | 스트림을 새로 시작 | 인식은 이어 가고, 확정 구간 끝 오디오 위치 + 560ms 이전에서 나온 토큰만 버림 |
| 공통 | faster-whisper large-v3-turbo `int8_float16`, Silero(무음 300ms, 최대 12초), 작업 스레드 2개 | 같음 |

코드는 브랜치 `feat/configurable-preview-stt`다. 프로필은 `STT_BACKEND_SYSTEM_AUDIO` 환경 변수로만 바꿔 서버를 다시 띄웠다(`.env`는 그대로).

## 3. 측정 방법

### 3.1 100초 스트림 6개 (`e2e_ws_eval2.py`)

재생은 `e2e_ws_eval.py`와 같다(PCM16 100ms 청크를 실시간 속도로 전송, 끝에 1초 무음, 6초 대기). 다른 점은 받은 메시지마다 도착 시각(재생 시작 기준)을 기록하는 것이다.

- 엔진마다 서버를 새로 띄우고, sherpa는 stream_02로 한 번 예열한 뒤 stream_00~05를 차례로 재생했다. Nemotron은 서버 기동 때 2초 무음으로 예열한다(`preload`).
- 받은 메시지는 `results\e2e_ws2_messages\<라벨>_<스트림>.json`에 남겼다. 라벨은 `sherpa_v1`, `nemotron_v1`이다.

지표:

| 지표 | 정의 |
|---|---|
| 회색 자막 CER | `segment_id`별 마지막 회색 자막(`preview`/`live_final`)을 처음 나온 순서대로 공백으로 이어 붙여 채점. 채점 규칙은 확정 CER과 같다 |
| 말소리 구간 | 원본 음성의 30ms RMS ≥ 0.05인 프레임. 0.35초 이하 쉼은 합치고 0.2초 미만 조각은 뺀다. 스트림 6개에 115개 |
| 회색 자막 첫 글자 | 말소리 구간 시작 → 그 구간 안(다음 구간 시작 전)에 처음 도착한 비어 있지 않은 회색 자막 |
| 안 나온 구간 | 위 시간 안에 회색 자막이 하나도 안 온 구간 수 |
| 말 끝 → 확정 도착 | 말소리 구간 끝 → 그 뒤 처음 도착한 `archive_final`. 확정보다 다음 말이 먼저 시작한 구간은 뺀다 (`final_latency_from_dump.py`) |

말소리 기준을 RMS 0.05로 둔 이유: FLEURS 녹음은 말 앞에 RMS 0.01~0.03 방 잡음이 1초 넘게 있어서, 0.005로 잡으면 잡음 시작을 말 시작으로 보고 첫 글자 지연이 1~1.7초 부풀었다.

### 3.2 30분 연속 (`long_session_eval.py 3 nemotron_30min`)

[실서버 검증](실시간_STT_실서버_검증.md) 5.4와 같다. 1분마다 기록하는 값에 회색 자막 메시지 수(`gray`)를 더해, 회색 자막이 중간에 멈추지 않는지 봤다. Nemotron 30분 시험은 사용자가 터미널에서 서버와 시험을 직접 돌렸다(백그라운드 실행은 PC 메모리 부족으로 두 번 중단됨).

최대값(약 3.3초)은 두 엔진 모두 stream_05에서 나왔다. 작은 목소리로 말이 이어지는 곳에서 RMS 0.05 기준이 말 끝을 너무 일찍 잡은 측정 오차다. 그래서 중앙값과 p90을 본다.

## 5. 구현하면서 찾은 문제

처음 구현(확정마다 회색 자막 스트림을 새로 시작)에서 stream_02를 재생해 확인한 문제와 고친 방법이다.

| 문제 | 원인 | 해결 |
|---|---|---|
| 회색 자막 앞말이 잘림 ("마찬가지로" → "마찬가", "1", "시간" 누락). 첫 글자 p90 2.4초 | 확정이 나올 때 엔진을 다시 시작하면 그사이 들어온 다음 말을 잃고, 새 세션은 첫 청크(약 0.5초)가 찰 때까지 글자를 못 낸다 | 인식 세션을 끊지 않고 화면용 텍스트만 새로 모은다 |
| 앞 문장 끝이 다음 회색 자막 앞에 붙음 ("는 일영국파운드의…") | 모델은 lookahead만큼 뒤 오디오를 보고서야 앞 오디오의 토큰을 낸다. 토큰 위치를 재 보니 말 끝 뒤 0.01~0.55초 위치로 기록됐다 | 확정 구간 끝 샘플 위치(`SpeechSegment.stream_end_sample`) + `streaming_latency_ms`(lookahead 6이면 560ms) 이전에서 나온 토큰을 버린다 |
| Nemotron이 whisper 모델 폴더를 자기 모델로 읽으려 함 | hybrid가 partial 모델 경로가 없으면 final 모델 경로를 넘겼다 | partial 모델 ID를 따로 주면 공통 경로를 넘기지 않는다 |
| 같은 모델로 generate() 두 개가 겹쳐 죽음 (`_encoder_finished` 없음) | 세션 정리가 5초 안에 안 끝나도 그 모델을 다음 세션에 줬다 | 제때 안 끝난 모델 인스턴스는 풀에 돌려주지 않고 버린다 |

## 6. 한계

- 회색 자막 CER은 숫자를 읽는 대로 적은 것("10시" → "열시", "1만" → "일만", "MDT" → "엠 디 티")도 틀린 글자로 센다. 실제로 읽기에는 표의 숫자보다 낫다.
- Nemotron이 외래어에서 엉뚱한 글자를 낸 경우가 있다 (stream_02 "솅겐" → "gา셴").
- 앞 문장 끝이 붙는 현상은 거의 사라졌지만 stream_02에서 한 번 남았다 ("는 일영국…").
- 세션은 한 번에 하나만 돌렸다. Nemotron은 세션마다 모델 인스턴스(GPU 약 1.2GB)를 따로 쓰므로 동시 세션 2개는 따로 재야 한다.
- 백프레셔로 회색 자막을 건너뛰면 회색 자막 쪽 오디오 위치가 확정 쪽과 어긋난다. 이번 측정에서는 백프레셔가 0회였다.
- 서버 기동 때 Hugging Face에 모델 정보를 조회한다. 모델 파일은 캐시에 있어 다시 받지는 않는다.
- 4장의 나머지 한계는 [실서버 검증](실시간_STT_실서버_검증.md) 8장과 같다(낭독 음성, Tauri 경로 미검증 등).

## 7. 재현 방법

```powershell
# 0) 최초 1회: Nemotron 의존성
cd D:\meeting-overlay-assistant
.\venv\Scripts\python.exe -m pip install -r requirements-nemotron.txt

# 1) 서버 (엔진만 바꿔 가며)
$env:AUTH_ENABLED="false"; $env:LIVE_STREAM_WORKER_COUNT="2"; $env:PYTHONIOENCODING="utf-8"
$env:STT_BACKEND_SYSTEM_AUDIO="hybrid_local_streaming_nemotron"   # 또는 hybrid_local_streaming_sherpa
.\venv\Scripts\python.exe -m uvicorn server.app.main:app --host 127.0.0.1 --port 8011

# 2) 측정 (다른 터미널)
cd D:\stt_eval
$env:PYTHONIOENCODING="utf-8"
$py = "D:\meeting-overlay-assistant\venv\Scripts\python.exe"
0..5 | % { & $py e2e_ws_eval2.py $_ nemotron_v1 }
python final_latency_from_dump.py nemotron_v1
& $py long_session_eval.py 3 nemotron_30min
```

| 파일 (`D:\stt_eval`) | 역할 |
|---|---|
| `e2e_ws_eval2.py` | 100초 스트림 재생, 확정·회색 CER, 첫 글자 지연 → `results\e2e_ws2.jsonl`, 메시지는 `results\e2e_ws2_messages\` |
| `final_latency_from_dump.py` | 저장된 메시지로 말 끝 → 확정 도착 지연 계산 |
| `long_session_eval.py` | 30분 연속 재생, 1분 간격 기록 → `results\long_session_<라벨>.json` |

`e2e_ws2.jsonl`의 `final_ms_*` 값 중 이 문서 이전 실행(`sherpa_v1`, `nemotron_v1`)에 들어간 것은 서버 `end_ms` 기준으로 계산해 틀린 값이다(기준 시각이 재생 시작과 어긋나 sherpa에서 음수가 나왔다). 이후 스크립트는 말소리 구간 기준으로 계산한다.
