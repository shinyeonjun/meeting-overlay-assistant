# 제품 범위 전략 설계 (DDD 하위 도메인 분석, 2026-10-13)

> 상태: **확정 (2026-10-13)**. 9장의 결정을 반영했다.
> 목적: 오버레이 HUD와 웹을 다시 설계하기 전에 **무엇이 이 제품의 핵심이고, 어느 화면이 무엇을 맡는지**를 정한다.
> 기술 쪽 DDD(바운디드 컨텍스트, 용어집, 컨텍스트 맵)는 [유비쿼터스 언어와 컨텍스트 맵](../architecture/유비쿼터스_언어와_컨텍스트_맵.md)과 [도메인 분석](../architecture/도메인_분석.md)에 이미 있다. 이 문서는 그 위에 **전략 설계**(하위 도메인 분류, 범위, 화면 배치)를 더한다.

## 1. 왜 이 문서가 필요한가

Tauri 실기 확인(2026-10-13)과 기능 조사에서 드러난 것:

- 서버의 컨텍스트 10개가 **모두 같은 무게로** 오버레이 한 창에 들어가 있다. 회의 중에도 로그인, 서버 주소, 회의 준비, 회사·상대방·스레드, 참여자 해석, 질문 보드, 리포트 상태, "다음 액션" 요약이 한 패널에 위아래로 쌓인다.
- 탭 전환 코드는 있지만 `index.html`에 탭 버튼이 없어 두 섹션이 동시에 보인다.
- 기존 [오버레이 UI/UX 명세](오버레이_UIUX명세.md)는 "진행 화면에서는 리포트·공유·히스토리를 보여주지 않는다"고 적었지만 구현은 그렇지 않다.
- 만들어 두고 쓰이지 않거나 닿을 수 없는 기능이 많다 (4장 표의 "현재 상태").

원인은 화면 설계 이전에 **하위 도메인의 우선순위가 정해지지 않은 것**이다. 핵심과 부가 기능이 구분되지 않으니 HUD가 모든 것을 떠안았다.

## 2. 제품이 푸는 문제 (도메인 비전)

> **온라인 회의에서 오가는 한국어 대화를 놓치지 않게 실시간 자막으로 보여 주고, 회의가 끝나면 믿을 수 있는 기록(정본)과 리포트를 남긴다. 음성은 PC 밖으로 나가지 않는다.**

- 주 사용처: 온라인 회의 (시스템 오디오 캡처, Windows 데스크톱)
- 차별점: **로컬·사내 설치**(음성이 외부로 안 나감) + **한국어 실시간 품질**
- 측정된 현재 품질 (같은 날 실서버 검증):
  - 확정 자막 정확도 약 92%
  - 회색 자막 정확도 약 87%, 첫 글자 약 0.55초
  - 근거: [실서버 검증](../research/실시간_STT_실서버_검증.md), [회색 자막 Nemotron 검증](../research/실시간_STT_회색자막_Nemotron_검증.md)

## 3. 하위 도메인 분류

| 하위 도메인 | 분류 | 이유 | 코드 컨텍스트 |
|---|---|---|---|
| **실시간 자막** | **핵심** | 제품을 쓰는 첫 번째 이유이자 차별점. 회의 중 사용자가 보는 유일한 필수 정보 | 실시간 캡처 (`live_capture`) |
| **회의 기록(정본)** | **핵심** | 회의 후 "믿을 수 있는 기록"이 두 번째 가치. 리포트·검색의 원천 | 후처리 (`post_processing`) |
| 회의 생명주기 | 지원 | 시작·종료·상태만 정확하면 된다. 규칙이 단순하다 | 회의 (`meeting`) |
| 리포트 | 지원 | 정본을 읽기 좋게 묶는다. 가치 있지만 정본 품질에 의존한다 | 리포트 (`reporting`) |
| 실시간 인사이트 (질문·결정·액션·리스크) | 지원 | 회의 중 보조. 기본값이 정규식 규칙이고 품질을 잰 적이 없다 | 인사이트 (`insight`) |
| 맥락 (회사·상대방·스레드) + 참여자 | 지원 | 회의를 이어 보는 데 도움. 하지만 CRM 성격이라 넓고, 현재 쓰임 근거가 없다 | 맥락 (`context`), 참여 (`participation`) |
| 지식·검색 | 지원 | 과거 회의 찾기. 서버는 있으나 화면에서 닿을 수 없다 | 지식 (`knowledge`) |
| 신원 (로그인·워크스페이스) | 일반 | 어느 제품에나 있는 기능. 기본값은 로그인 끔 | 신원 (`identity`) |
| 운영 관측 | 일반 | 운영자용 지표. 사용자 화면에 둘 이유가 없다 | 운영 (`operations`) |

**핵심 도메인에 투자를 모으고, 지원·일반 도메인은 화면에서 한 발 물린다**가 이 분석의 결론이다. 특히 회의 중 화면(HUD)은 핵심 도메인 하나, 실시간 자막만을 위한 곳이어야 한다.

## 4. 기능 현황과 범위 제안

"현재 상태"는 2026-10-13 코드 조사 결과다.

| 기능 | 하위 도메인 | 현재 상태 | 제안 |
|---|---|---|---|
| 실시간 자막 (회색 → 확정) | 핵심 | 오버레이. 동작함 (자막 목록 버그는 PR #15에서 수정) | **HUD의 주인공** |
| 회의 시작·일시정지·종료 | 지원 | 오버레이. "준비 → 시작" 2단계, 일시정지 없음 | **HUD. 원클릭 시작**, 일시정지 추가 |
| 입력 소스 선택 | 지원 | 오버레이 준비 화면 | HUD 설정(기어)으로. 기본 시스템 오디오 |
| 회의 제목 | 지원 | 오버레이 준비 화면 (필수 흐름) | 자동(날짜·시각). 회의 중·후에 바꿈 |
| 정본·전사본·녹음 재생 | 핵심 | 웹 | **웹** 유지 |
| 리포트 생성·보기 | 지원 | 웹. 오버레이에 상태 배지 중복 | **웹**. HUD는 종료 직후 "웹에서 보기" 한 번 |
| 리포트 공유 | 지원 | 서버만 있음. 화면 없음 | **보류** (9장 결정) |
| 실시간 질문·결정·액션·리스크 | 지원 | 오버레이: 질문 보드만. 결정·액션·리스크 목록과 편집기는 화면 요소가 없음 | **9장 결정**. 추천: HUD에는 눌러서 보는(pull) 작은 표시만 |
| 현재 주제 | 지원 | 주제 이벤트가 꺼져 있어 늘 비어 있음 | HUD에서 **뺀다** |
| 회사·상대방·스레드 선택 | 지원 | 오버레이 고급 설정 안 | HUD에서 **뺀다** → 웹(회의 전후) 또는 보류 (9장) |
| 참여자 입력·해석·후속 작업 | 지원 | 오버레이 고급 설정 안 | HUD에서 **뺀다** → 웹 또는 보류 (9장) |
| carry-over·검색 브리프 | 지원 | 웹 홈에 일부 | 웹 |
| 검색 (retrieval) | 지원 | 서버 있음. 웹 화면(`Assistant.jsx`)이 어디서도 열리지 않음 | **9장 결정** |
| 히스토리 타임라인 | 지원 | 서버·API 래퍼 있음. 호출하는 곳 없음 | 보류 |
| 웹 "AI 어시스턴트" 입력창 | — | 입력·전송 버튼이 동작하지 않음 | 웹에서 **지우거나** 검색과 연결 |
| 웹 캘린더·설정 메뉴 | — | 눌러도 아무것도 안 함 | 웹에서 **지운다** |
| 로그인 | 일반 | 오버레이 첫 화면 (기본은 로그인 꺼짐) | 켜진 서버에서만 최초 1회. HUD 본화면에 두지 않음 |
| 서버 주소 (control·live) | 일반 | 오버레이 첫 화면 | **설정 화면**으로. 저장값이 환경 변수를 덮는 문제(6번) 해결 |
| 운영 지표 (지연, 백프레셔) | 일반 | 오버레이에 숨긴 블록 | 운영 콘솔 (`server-admin`)만 |
| "다음 액션" 요약 | — | 오버레이 모든 단계에 표시 | **뺀다** (원클릭 흐름이면 필요 없음) |

## 5. 화면 배치 (어느 표면이 무엇을 맡나)

| 표면 | 맡는 하위 도메인 | 쓰는 때 | 원칙 |
|---|---|---|---|
| **오버레이 HUD** | 실시간 자막 + 회의 생명주기(시작·일시정지·종료) | 회의 중 | 한 가지 일만 한다. 다른 앱 위에 떠 있으니 작고 조용해야 한다 |
| **HUD 설정** (기어 하나 뒤) | 입력 소스, 글자 크기·투명도·위치, 서버 주소 | 처음 한 번, 가끔 | 회의 흐름에서 분리한다 |
| **웹 워크스페이스** | 회의 기록(정본), 리포트, 검색, 맥락·참여 | 회의 전후 | 읽고 정리하고 찾는 곳 |
| **운영 콘솔** | 운영 관측, 설정 프로필, 로그 | 운영자 | 사용자 화면에 노출하지 않는다 |

## 6. 회의 단계별 사용자 흐름 (목표)

| 단계 | 사용자 행동 | 표면 | 지금과 다른 점 |
|---|---|---|---|
| 준비 | (선택) 웹에서 지난 회의 확인 | 웹 | 회의 준비가 시작의 필수 단계가 아니다 |
| 시작 | HUD에서 **시작 한 번** | HUD | "준비 → 시작" 2단계, 제목 입력 없음. 제목은 자동 |
| 진행 | 자막을 본다. 필요하면 일시정지, 접기, 이동 | HUD | 패널 없이 자막과 작은 컨트롤 바만 |
| 진행 (선택) | 질문·액션 표시를 눌러 본다 | HUD | 9장 결정에 따름 |
| 종료 | **종료** → 확인 → "웹에서 기록 보기" 안내 한 번 | HUD | 리포트 상태 배지를 HUD에 계속 두지 않는다 |
| 정리 | 정본·리포트 확인, 제목 수정, 공유 | 웹 | 변화 없음 (웹 정리는 별도 작업) |
| 기록 | 지난 회의 찾기 | 웹 | 검색을 화면에 연결할지 9장 결정 |

## 7. HUD 설계 원칙 (조사에서 가져온 것)

비슷한 제품(Windows·macOS 라이브 캡션, Teams·Zoom·Meet 자막, Granola, Fireflies, Read.ai, Copilot 등)이 공통으로 따르는 것:

1. **평소엔 작게, 필요할 때 펼친다.** 접힌 알약(pill)이나 바, 소리 없으면 자동으로 숨기기 (macOS, Granola, Fireflies, Chrome)
2. **2~3줄, 왼쪽 정렬, 아래에서 위로 쌓는다.** 지난 줄은 별도 스크롤이나 패널 (DCMP·BBC: 한 번에 2줄, 많아야 3줄)
3. **이미 뜬 글자는 흔들지 않는다.** 새 글자는 덧붙이고, 줄 배치가 바뀌는 고쳐 쓰기는 피한다. 사용자는 정확도보다 안정성을 고른다 (Google 연구, CHI EA 2023)
4. **읽기 쉬운 기본값 + 사용자 조정.** 반투명 어두운 상자 위 흰 산세리프. 글자 크기·투명도는 기어 하나 뒤에서 조정한다 (DCMP, W3C). 지금 HUD는 배경이 너무 투명해 뒤 글씨가 비친다 (실기 3번 문제)
5. **화자 표시는 발화가 바뀔 때 한 번만, 그리고 잠정적으로.** 화자 정보가 없으면 붙이지 않는다. 지금처럼 모든 줄에 "LIVE:"를 붙이지 않는다 (실기 4번 문제)
6. **인사이트는 주로 눌러서 본다(pull).** 알아서 띄우는 것(push)은 많아야 한 가지, 말 중간에 팝업 금지 (Copilot, Zoom AI Companion, Fireflies)
7. **명시적이고 가벼운 시작.** 원클릭 시작·일시정지·종료, 녹음 중 표시는 항상 보이게. 몰래 녹음하지 않는다 (Granola·Otter 소송 사례)
8. **옮기고, 크기 바꾸고, 위치를 기억한다.** 중요한 내용을 가리지 않는다. 화면 공유 때 숨기기는 선택지로 둔다
9. **설정·리포트·기록은 본 앱(웹)에.** HUD에 두지 않는다 (Granola, Fireflies, Otter, Read.ai 모두)
